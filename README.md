# 언론보도 실시간 모니터링 및 통계 자동화 시스템

고려대학교 구로병원 홍보팀 기능명세서(v1.0, 2026-08-20)를 그대로 구현한 Google Apps Script 프로젝트입니다.
서버·DB 없이 **구글 스프레드시트 + Apps Script**만으로 동작하도록 만들었습니다(명세서 1.4 구축 원칙).

## 2. 배포 방법 (담당자가 직접 진행)

### 방법 A — 복사/붙여넣기 (권장, 별도 도구 불필요)

1. [sheets.google.com](https://sheets.google.com)에서 새 스프레드시트를 만듭니다.
2. 메뉴 **확장 프로그램 → Apps Script**를 클릭합니다.
3. 기본 생성된 `코드.gs`를 지우고, 이 폴더의 `.gs` 파일 14개를 각각 **파일 → 새로 만들기 → 스크립트**로 만든 뒤 내용을 그대로 복사해 넣습니다(파일명은 확장자 `.gs` 없이 그대로 사용).
4. 좌측 `appsscript.json`은 편집기의 ⚙️ **프로젝트 설정**에서 "appsscript.json 매니페스트 파일을 편집기에 표시" 체크 후 내용을 덮어씁니다.
5. 저장 후 스프레드시트로 돌아와 새로고침하면 상단에 **[모니터링 시스템]** 메뉴가 나타납니다.

### 방법 B — clasp (Node.js/CLI에 익숙한 경우)

```bash
npm install -g @google/clasp
clasp login
clasp create --title "언론보도 모니터링" --type sheets
clasp push
```

`clasp create`가 만든 스프레드시트를 열어 방법 A의 5번부터 이어서 진행합니다.

## 3. 스크립트 속성 등록 (필수 — API 키는 절대 시트에 적지 않음)

Apps Script 편집기 → ⚙️ **프로젝트 설정 → 스크립트 속성**에서 아래 키를 등록합니다.

| 키 | 설명 | 필요 시점 |
|---|---|---|
| `NAVER_HUB_KEY_ID` / `NAVER_HUB_KEY` | **[기본]** NAVER API HUB에서 발급받은 인증키 (`X-NCP-APIGW-API-KEY-ID` / `X-NCP-APIGW-API-KEY`) | 1단계(수집) |
| `NAVER_API_MODE` | 기본값 없음(=HUB). 기존 개발자센터 키를 아직 쓰는 경우에만 `LEGACY`로 설정 | 필요 시 |
| `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` | `NAVER_API_MODE=LEGACY`일 때만 사용하는 구(舊) 개발자센터 키 (2027-06-30까지만 지원) | 필요 시 |
| `NAVER_API_BASE` | 호스트를 수동으로 덮어써야 할 때만 설정(기본값은 모드에 따라 자동 선택됨) | 필요 시 |
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` / `SOLAPI_SENDER` | 알림톡·SMS 발송 대행사(SOLAPI 등) 키와 발신번호 | 3단계(위기 알림) |
| `KAKAO_PF_ID` / `KAKAO_TEMPLATE_CODE` | 카카오 비즈니스 채널 발신프로필ID, 승인된 알림톡 템플릿 코드 | 3단계 |
| `MESSAGE_BALANCE_ALERT_THRESHOLD` | 잔액 경고 기준(원), 기본 5000 | 선택 |

### 3.1 NAVER API HUB 키 발급 절차 (2026-08 기준)

네이버 검색 API는 2026-06-25 **NAVER API HUB** 출시로 신규 발급 창구가 완전히 바뀌었습니다.
기존 개발자센터(developers.naver.com)에서는 더 이상 새 애플리케이션을 만들 수 없고
(2026-07-31 신규 발급 종료), 아래 절차를 따라야 합니다.

1. **네이버클라우드플랫폼(NCP) 계정 준비** — [ncloud.com](https://www.ncloud.com)에서 회원가입/로그인합니다. 기존 개발자센터 계정과는 별개의 플랫폼입니다.
2. **NAVER API HUB 콘솔 진입** — NCP 콘솔에서 "NAVER API HUB" 제품(또는 [ncloud.com/product/applicationService/naverApiHub](https://www.ncloud.com/product/applicationService/naverApiHub) 소개 페이지의 콘솔 바로가기)으로 이동합니다.
3. **Application 생성** — 새 Application을 만들고, 사용할 API로 **검색(뉴스/카페글/블로그)**을 선택합니다.
4. **인증키 발급 확인** — Application 생성이 끝나면 인증키 2개가 발급됩니다. 이 값을 각각 스크립트 속성 `NAVER_HUB_KEY_ID`(→ `X-NCP-APIGW-API-KEY-ID`), `NAVER_HUB_KEY`(→ `X-NCP-APIGW-API-KEY`)에 등록합니다.
5. **테스트 호출로 검증** — HUB가 출시된 지 얼마 되지 않아 응답 필드가 공지와 다를 가능성이 있으므로, 콘솔의 API 테스트 도구나 curl로 한 번 직접 호출해 `items[].title/link/description/pubDate` 필드가 그대로인지 확인한 뒤 트리거를 설치하세요.
   ```bash
   curl -G "https://naverapihub.apigw.ntruss.com/search/v1/news" \
     -H "X-NCP-APIGW-API-KEY-ID: 발급받은_KEY_ID" \
     -H "X-NCP-APIGW-API-KEY: 발급받은_KEY" \
     --data-urlencode "query=고려대 구로병원" --data "display=5"
   ```
6. **한도 확인** — 2026-08 기준 검색 API는 전 종류 합산 **월 775,000건**, 키당 **초당 50건(RPS)** 한도로 한시적 무료 운영 중이며 초과 시 HTTP 429가 반환됩니다(추후 유료 전환 예정). `03_CollectNaver.gs`는 429 응답을 오류가 아닌 "한도 초과"로 별도 처리하고, `13_Ops.gs`의 F-107 로직이 월 사용량 80%/100%에서 자동으로 경고·완화합니다. 요금·한도는 변경될 수 있으므로 콘솔에서 최신 값을 재확인해 `00_설정!임계값`의 `네이버_API_월간한도`를 맞춰 두세요.

> 이미 개발자센터에서 발급받은 기존 키가 있고 2027-06-30 전까지만 쓰고 넘어가려면, 새로 발급받지 않고 `NAVER_API_MODE=LEGACY` + `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET`로 그대로 운영할 수 있습니다. 다만 신규 구축이므로 처음부터 HUB로 시작하는 쪽을 권장합니다.

## 4. 최초 실행 순서

1. 스프레드시트에서 **[모니터링 시스템 → 1. 초기 설정 실행]** — 9개 시트가 자동 생성되고 00_설정에 기본 키워드/위기사전/임계값이 채워집니다.
2. **00_설정** 시트를 열어 다음을 확인·보완합니다.
   - 검색 키워드(기관명 표기 변형, 인물명, 센터·사업명)
   - 매체 마스터(자주 등장하는 매체를 미리 등록해 둘수록 F-203 정규화 정확도가 올라갑니다)
   - RSS 피드(구글 알리미 URL은 직접 발급받아 붙여넣어야 합니다 — https://www.google.com/alerts)
   - 수신자 목록(연락처, 수신등급에 `관심,주의,경계,심각,리포트` 중 해당하는 값을 쉼표로 입력, 수신동의=Y)
3. 3번 항목의 API 키를 스크립트 속성에 등록합니다.
4. **[모니터링 시스템 → 2. 트리거 설치]** — 5분 주기 수집, 대시보드 갱신, 야간/일일 알림 배치, 주간/월간 리포트, 백업, 보도자료 매칭, 잔액확인 트리거가 한 번에 등록됩니다.
5. **[지금 즉시 수집 실행]**으로 수동 1회 실행해 01_모니터링현황에 기사가 쌓이는지 확인합니다.

## 5. 단계적 롤아웃 (명세서 8.2항과 동일한 순서를 권장)

- **1단계**: 네이버 키만 등록하고 수집·중복제거·자동적재만 먼저 확인 (알림 관련 키는 비워둔 채로 두면 알림 발송은 자동으로 건너뛰고 로그만 남습니다).
- **2단계**: 논조/카테고리/진료과 자동 분류값을 담당자가 검수하며 00_설정의 키워드 사전을 보강. 주간/월간 통계·대시보드 메뉴로 확인.
- **3단계**: 카카오 비즈니스 채널 개설 + 알림톡 템플릿 심사 신청(영업일 3~7일 소요, 반려 가능성 있으므로 미리 시작). 승인 전까지는 SOLAPI 키만 넣어 SMS 경로부터 먼저 검증 가능(카카오 키가 비어 있으면 자동으로 SMS로 대체 발송됩니다).
- **4단계**: 커뮤니티 수집(00_설정!임계값의 `커뮤니티수집_사용`을 Y로 변경), 연간 통계, 리포트 메일 발송 확인, 위기 등급 임계값을 실제 오탐/미탐 사례로 튜닝.

## 6. 운영 중 자주 쓰는 메뉴

- **지면·방송 보도 수동 등록**: 온라인 미노출 보도를 입력(F-104)
- **선택한 기사에 수동 알림 발송**: 자동 판정을 거치지 않고 즉시 알림(F-509)
- **선택한 기사를 오탐으로 표시**: 위기 오탐 시 클릭 — 매칭된 키워드가 예외 목록에 쌓여 다음부터 자동 제외됩니다(F-512)
- **보도자료 채택 매칭 실행**: 02_보도자료 입력 후 실행하면 채택률이 갱신됩니다(F-208)
- **연간 아카이브 실행 / 모니터링 현황 백업 실행**: 수동 실행도 가능(트리거로도 자동 실행됨)

## 7. 알아두어야 할 제약·주의사항

- **저작권**: 기사 전문은 저장하지 않고 제목·요약(약 200자)·링크만 보관합니다(명세서 3.2, 9장).
- **개인정보**: 환자·보호자 식별정보, 커뮤니티 작성자 신상정보는 어떤 컬럼에도 저장하지 않도록 설계되어 있습니다. 요약 자동 절단 로직이 있지만, 검수 시 개인정보가 요약문에 섞여 있지 않은지 담당자가 확인해야 합니다.
- **위기 등급 임계값**: `00_설정!임계값` 블록의 점수 기준은 초기값입니다. 운영 첫 1개월은 오탐·미탐을 관찰하며 조정하세요(6.3항 원칙).
- **SOLAPI 연동**: `07_Alert.gs`의 인증 헤더 생성(HMAC-SHA256)과 엔드포인트는 SOLAPI 공식 문서를 기준으로 작성했습니다. 실제 계약 후 최신 API 문서와 대조해 확인하세요.
- **NAVER API HUB**: 요금·한도 정책이 바뀔 수 있으므로 착수 전 공식 페이지에서 최신 조건을 확인하세요.
- **권한 관리(F-602)**: 01_모니터링현황은 홍보팀만 편집 가능하도록 스프레드시트 공유 설정에서 "편집자"를 홍보팀으로 제한하고, 경영진·유관부서에는 "뷰어" 또는 리포트 메일만 공유하세요(코드가 아닌 구글 시트 공유 설정에서 처리).
- **엑셀 다운로드(F-306)**: 구글 시트 기본 기능(파일 → 다운로드 → Microsoft Excel)을 그대로 사용하면 됩니다.
